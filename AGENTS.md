# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot, Windsurf…)
and for humans working in this repository. `CLAUDE.md` imports this file.

## Rule 1: Every feature's docs and specs live in its own feature folder

All feature documentation and specifications live in
**`docs/spec/<feature>/`**, one folder per feature (epic).

```
docs/spec/
  <feature>/                 # folder name = full feature/epic name in kebab-case
    analysis.md              # requirements analysis / problem statement (optional)
    spec.md                  # specification: what and why
    plan.md                  # implementation plan: how and in what order
    tasks.md                 # task breakdown / checklist (optional)
    <spec-id>.spec.md        # machine-checkable CatSpec specs (optional)
    <spec-id>.lock.json      # generated by CatSpec next to its spec; never edit by hand
    examples/                # transcripts, sample inputs/outputs (optional)
```

1. **The parent folder is the feature name.** Use the *full* epic name in kebab-case,
   with no abbreviations, numbers or dates. Example: the epic "React SDD" →
   `docs/spec/react-sdd/`; "Reactive AST-Linked Spec Engine" →
   `docs/spec/reactive-ast-linked-spec-engine/`.
2. **Fixed file names, no numbering.** Use exactly `analysis.md`, `spec.md`, `plan.md`,
   `tasks.md`. Not `01-spec.md`, `spec-v2.md` or `<feature>-plan.md`. The folder already
   says which feature it is.
3. **Before starting work on a feature**, read `docs/spec/<feature>/spec.md` and `plan.md`.
   If the folder doesn't exist and the change is more than a small fix, create it and
   write `spec.md` (and `plan.md`) **before** writing code.
4. **One feature, one folder.** Extend the existing folder, don't create a sibling. Don't
   rename a folder without updating every link to it.
5. **Spec and code change together.** If code changes behaviour that a spec describes,
   update the spec in the same commit or PR.
6. **Nowhere else.** No design notes in the repo root, no `docs/<file>.md` outside
   `docs/spec/`, no `specs/`, `.specs/` or `design/` folders, no docs next to source code.
7. Use relative links. Files in the same folder link as `./spec.md`.

## Rule 2: Architecture decisions live in `guidelines/architecture/reactive-ast-adr.md`

`guidelines/architecture/reactive-ast-adr.md` is the **single** architecture decision log and the
architecture spec of the whole repository. Its frontmatter holds the global rules that
CatSpec enforces (`type: architecture`); its body holds the decisions.

1. **Read the ADR log before any non-trivial change.** Code must not contradict an
   `Accepted` ADR.
2. **Record every architectural decision there**: package boundaries and dependency
   direction, new runtime dependencies, data and file formats, public APIs and CLI
   contracts, cross-feature patterns, and changes to this layout. Decisions that affect
   only one feature's internals stay in that feature's `spec.md`.
3. **Append-only.** Add `## ADR-NNN: <title>` with the next number, using the format
   *Status · Date · Context · Decision · Consequences*. Never renumber or delete an
   entry. To change a decision, add a new ADR that supersedes it and mark the old one
   `Superseded by ADR-NNN`.
4. **Make it checkable when possible.** If a decision can be verified in code, add a rule
   to the ADR log's frontmatter with `adr: ADR-NNN`.
5. Don't create other ADR files or folders (`ADR.md`, `docs/adr/`, `<feature>/adr/`, `decisions/`).
6. Other project-wide guidelines go in `guidelines/<topic>/` (e.g. `guidelines/coding/`),
   never in `docs/spec/`.

## Exceptions

The standard root files stay where tools expect them: `README.md`, `AGENTS.md`,
`CLAUDE.md`, `LICENSE`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md`,
`CODE_OF_CONDUCT.md`, and GitHub templates in `.github/`.
